## Evidence boundary

Real headless Chrome runs in fresh temporary profiles. CDP dispatches actual mouse and keyboard events; synthetic standard gamepad buttons enter through `navigator.getGamepads` and the game's normal polling paths. Network checks use bundled PeerJS, the normal public signaling service and real DataConnections between profiles on the same Windows PC/network. The real transport checks include create/join, missing/full room refusal, a deliberately modified legacy-capability hello refusing Roomier, visible host/guest HUD Menu, timer completion while Options is open, host loss during match/results/Cup, and deliberate `Peer.disconnect()` preserving existing DataConnections and host Start while hiding sharing.

Fault checks explicitly inject FakePeer errors and late callbacks, deferred/failed script loading, a silent admission peer, suppressed snapshots on an otherwise live DataConnection, and document-hidden visibility events. Real15-second deadlines run without clock acceleration. These injections test recovery semantics; they are not evidence of naturally occurring transport failure or a real minimized/suspended Windows game. Rewards/progress/collection receipts are compared before/after interruption; completed results remain preserved and incomplete matches receive no award. The results-departure fixture forces authoritative `endMatch`; the Options-results transition shortens the ordinary host timer to trigger the game's actual completion path.

The suite also checks remembered rules/settings/outfit/progress around failed operations, host keyboard seat continuity, both keyboard seats neutral while Match menu is open, synthetic pad Cancel/Start/Resume, visible focus, and affected offline/practice pause/Resume/Leave. Computed rendered visibility checks cover nonempty pending/error/online-Menu explanation text with a visible, enabled, hit-testable Cancel/Retry/Resume companion at800x600 and800x500. They check ancestor display/visibility/opacity/clipping, text bounds, viewport bounds and `elementFromPoint`; the actual screenshots were also visually inspected. These are bounded visibility checks, not TV-distance or human accessibility acceptance.
