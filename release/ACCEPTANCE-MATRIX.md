# Complete-experience acceptance matrix

13 October 2026 · Proposed verification protocol, not a record of passes

Read [FULL-EXPERIENCE-PLAN.md](FULL-EXPERIENCE-PLAN.md), [ROADMAP-STATUS.md](ROADMAP-STATUS.md) and the [beta.7 export record](PREVIEW-BUILD.md) first. Coding completion, automated verification, human/device acceptance and platform approval are separate states. Current technical evidence remains version-scoped; all cases below are pending unless an existing linked record covers unchanged code and dependencies.

## Record the supported journey and its terminal result

For each run record runtime/package SHA, settings/seed, OS/CPU/GPU/RAM/display, physical device/model/connection, input assistance, topology, household networks/RTT, human/bot counts, fresh or migrated isolated profile, expected/observed result, severity, evidence and reviewer. Use copied legacy saves and clean QA profiles; never modify the owner's normal profile or close their running game. A test pass must name the promise it covers.

Topology labels: L1 = solo; L2/L4 = two/four local seats; N = individual native guests; H2+2 = two host-local plus two individual guests; H4+1/H4+4 = four host-local plus one/four individual guests; S4+4 = two four-person sofas on two PCs, blocked until new guest multiseat protocol; RPT = Steam-streamed host-local seats, separate from native; F = faction one-localId client. Arena total is at most eight humans. Faction couch/co-op Story are not existing supported arrangements.

## Every mode needs a complete objective, failure and reset

Use one input-only local complete match and one supported native host/guest complete match for each arena mode. Repeat input ownership/reward-sensitive cases with local couch roles. Every advertised mode also receives a complete human match. Test bot objectives at all four difficulty profiles with deterministic seeds. Group high-risk cases deliberately rather than running every device × mode × map × difficulty × chaos combination.

Mandatory three-way hotspots: Rooftop + Race + Roomier; ice + dash + knockback; online + weapon upgrades + death; four seats + pad reconnect + Cup; cinematic + pause + controller focus; rare power + disconnect + rematch. Geometry has full coverage because paths/hazards differ; use pairwise coverage for lower-risk settings. Rerun affected regressions after changes, reuse unaffected frozen evidence transparently, and always smoke the new package's menus, gameplay, save/restart and included media.

## Humans accept comprehension, participation and reasons to continue

Use the plan's six-group/24-person formative sample and separate fresh solo sessions; it is not statistically powered retention research. Offer Another Cup and Stop equally, capture every participant's assent, longest idle interval, unexplained deaths, contribution/score explanations, prompts required, domination complaints, character/causality recall, stopping reasons and voluntary seven-day return choices. Proposed targets: ready group launch <90 seconds after onboarding, Cup 8–12 minutes, no >30-second truly idle segment in recommended rotation. Repeated confusion/disengagement triggers revision; actual counts and comments remain the evidence. Do not convert a rematch click, bot result, reward equip or QA pass into fun/retention acceptance.

Zero open P0/P1 in advertised scope before FE-18. P0 covers crash/data loss/security; P1 blocked progression/input/objective/result or severe repeatable stall; P2 material readability/confusion/balance; P3 cosmetic. A P2 exception requires accepted limits and reproducible evidence. Native Node/Python faults need a new bounded investigation and proved tooling/game boundary, not lucky reruns. Proposed performance budgets and network impairments are in the main plan; measurements must name hardware and show distributions. External Steam/hosting/human/device gates remain separate from code completion and repository merge.
