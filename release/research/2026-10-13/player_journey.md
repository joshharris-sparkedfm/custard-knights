# Custard Knights player journey, menus, accessibility and UI art

## What exists, and where does the current experience lose clarity?

### Takeaway
The shipped beta.7 has substantial functional menu, local/online and collection machinery; the next step is to unify it into an intentional game front end, not add a dashboard or remove working features. The evidence supports inconsistent hierarchy and interaction contracts, not a claim that every menu is broken.

### Inferences / proposed target
1. P0 home: illustrated bakery/castle courtyard with the accepted 3D knight as a genuine focal point, restrained animated details; four main routes **Quick Brawl**, **Story: The Great Pudding War**, **Play with Friends**, **Faction Front**. Wardrobe/Options/How to Play/Quit in a stable utility strip. Cup lives in the Play with Friends/arena format picker, remains accessible solo; custom settings are behind Quick Brawl's Customize. No carousel, news feed, generic SaaS card wall or excessive submenu depth.
2. First launch: short accessible setup (text size, motion/flashing, audio, input test), then “Learn by playing” or “Jump straight in.” No forced sign-up or telemetry consent; reporting remains off and optional. Story introduces its own mechanics in play; optional training covers arena combat without requiring the long text manual.
3. Returning player: preserve layout. Story item changes to **Continue Story — [named objective]**, with chapter/replay beneath. Quick Brawl uses last safe selected configuration with a concise visible summary; never silently raises difficulty/chaos. Remember last menu focus, not an accidental input that immediately launches combat.
4. Play with Friends: choose **This PC** or **Online Room**, then single match/Cup. Seat screen identifies each device and character, lets players join/leave/change outfit without shifting someone else's seat. Online room shows human/bot totals, party slots, all rules/map/size, host ownership, each readiness/loading state and copy-code action. Never expose a private host access key in a share link.
5. Faction Front remains a separate large-battle choice; show army size as `50 vs 50 · 100 total`, with a human/bot split. Bot practice and private online session separate. Never imply public matchmaking exists if hosting is not deployed. 100vs100 is not merely copy change; covered by server agent.
6. P0 common navigation contract: A/Enter/Space activate, B/Escape back one level, arrows/D-pad move spatially, Tab logical sequential order, clear high-contrast focus and persistent bottom prompts; inputs do not activate behind modals. Restore focus after popup or rerender; scroll focused item into view; preserve selections on Back. Keep controller text entry workable, paste full codes, trim harmless whitespace, explicit Join rather than unexpectedly joining on last character. These are proposed rules, not all currently verified.
7. P0 gameplay menu: single-player/story/bot practice pause simulation/audio appropriately; shared local pauses for all seats with clear ownership; online opens **Match menu — match continues**, neutralizes that player's held inputs but never freezes the host. Options accessible in-game; Resume default, Leave destructive confirmation only when progress/session consequence exists. Controller loss local pauses and offers reconnect/reassign; online announces loss/neutral input with an explicit timeout policy, never silently shifts seats.
8. P1 results: first show who won, why, your objective contribution and one memorable earned award. Then Rematch primary, Change Rules secondary, Leave tertiary. Online Rematch preserves room/identities and visibly waits for host/readiness. Reward notification may offer Equip/Keep Look without hijacking rematch focus. Story success presents consequence, autosave state and Continue; do not bury story consequences behind optional tiny “watch next” buttons.
9. P1 wardrobe: character stage + category tabs (helm/visor/outfit/weapon appearance/chicken); goal drawer and three saved outfits; preview at gameplay size, compare locked/owned/equipped clearly. Retain current ownership, save format and no paid advantage. Narrative faction silhouette must remain recognisable under cosmetics.
10. P1 options grouped Controls / Audio / Display & Accessibility / Gameplay / Save & Support. Separate advanced local play reports/research under Support; experiments are not ordinary player setup. Add measured text scale, control remapping/presets, deadzone/aim options where implemented, subtitle background/size, toggle alternatives for holds; no checkbox promised before its runtime behavior is verified. Existing reduced flash and shake settings preserved.
11. Error copy targets: missing room: “That room could not be found. Check the code or ask your friend for a new invite.” actions Edit code/Retry/Back; host left: “The host ended this room. Your saved progress is safe.” only if progress persisted; incompatible build: show local/required version and update route; joining late: “Match in progress. You will join the next round.”; failed asset load: Retry/Return to menu plus export diagnostics; save failure: “Progress could not be saved on this PC” plus retry/backup without claiming success. Do not promise reconnect for PeerJS where no recovery exists; ranked reconnect policy separately documented.

### Gaps

No novice/controller/accessibility participants observed; no satisfaction/retention score invented. Need capture all specified screens at actual desktop sizes as part of implementation review.

## Which references should guide the visual and interaction direction?

### Takeaway
Lock the game's own rounded art and custard/purple identity as the primary source; use Refero to improve composition and concrete interactions. The external sources are references, not a claim that a language app or website is a battle-game usability benchmark.

### Cited Findings
- Three Refero style searches were performed: “playful illustrated game fantasy bright cartoon”, “Nintendo gaming bold colourful character”, “handcrafted warm illustrated adventure”. Ten previews returned per search, with overlaps. Three full styles inspected: Playdate `c91209ef-f7f3-4d2b-bf69-41b58e4e2cc2`, Wayfinder `168f20ae-b58e-4781-b9b8-46b2d9b81b5f`, Duolingo `fad6cd55-121c-4050-bfa9-f7cccbf81d78`. [Playdate](https://play.date), [Wayfinder](https://wayfinder.nfb.ca), [Duolingo](https://www.duolingo.com). Source is live Refero extraction, not direct live-site inspection.
- Playdate's full style emphasizes one clear visual anchor, strong yellow/charcoal contrast, compact legible type hierarchy, simple surfaces, and real product/game imagery. Its violet is an action accent in that source. Wayfinder emphasizes full-bleed illustrated atmosphere and minimal chrome; its ghost controls and tiny subtle text should NOT be inherited. Duolingo provides rounded clear controls and approachable progressive disclosure, but its green/white branding is rejected. Full-style extraction contains inconsistent token instructions (e.g. Duolingo primary filled versus outlined CTA), so no blind token copying. [Refero source sites above](https://play.date).
- Screen search “Discord voice channel invite friends game” inspected candidate metadata; two complete screens opened: Xbox session-code `a0dc8e6f-b194-47d8-b697-a4056d398a35` and Discord invite `d7c2a6fd-a07f-476c-bb97-9c172fb8c3e5`. The Xbox screenshot was visually inspected; centered code input with one clear explanation and dismiss path, background dimmed. [Xbox screen](https://refero.design/pages/a0dc8e6f-b194-47d8-b697-a4056d398a35), [Discord screen](https://refero.design/pages/d7c2a6fd-a07f-476c-bb97-9c172fb8c3e5).
- One full flow inspected: Xbox **Join by session code**, ID7711, four screens: entry, empty code, code entry, not-found/re-enter. Success path is explicitly NOT shown; cannot treat it as successful-join evidence. Duolingo onboarding search was exploratory, not chosen as a game reference. [Xbox flow](https://refero.design/flows/7711).
- Microsoft XAG101 recommends readable default game text and configurable scaling; at1080p its PC target is18px rendered body-height, console26px. It discusses measuring actual rendered characters, not assuming CSS font-size equals perceived size. [XAG101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101).
- XAG107 recommends complete keyboard operation and configurable analog sensitivity; XAG112 stresses accessible settings from first launch, consistent activation/back semantics, logical focus, and digital controller/keyboard navigation. These are useful design/testing references, not Steam certification requirements. [XAG107](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107), [XAG112](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112).

### Inferences / reference lock
- PRIMARY: actual Custard Knights rounded models, expressive saucepan helmets, cream/custard against deep purple. The hero/scene should establish a playful physical world. Existing model screenshots and user preference outrank web marketing aesthetics.
- PRESERVE: rounded helmets/bothvisors, bold readable yellow identity, tactile simple outlines, character silhouette, clean gameplay visibility. Character illustration owns the dominant visual area; controls remain immediately readable without hover.
- BORROW ONLY: Playdate's disciplined single focal object and clear hierarchy; Wayfinder's world-backed composition (not black/ghost controls); Xbox/Discord's isolated invite task and explicit recovery/copy state.
- ROLE RULES: yellow highlights primary action/focus, not every decoration; secondary controls neutral purple/cream; faction colours identify allegiance plus shape/emblem, never sole distinction. Danger red reserved failure/danger. Art never carries critical objective instructions without text/symbol counterpart.
- TYPE: retain playful display face only for short titles; use a readable licensed UI family for body/captions. Audit font-file distribution rights before embedding replacements; no claim Adobe subscription grants game font redistribution.
- MOTION: a small ambient loop/hero idle, quiet on selection, clear fast feedback; reduced-motion setting removes bobbing/background loops while preserving static cues. Avoid constant bouncing cards, auto-rotating banners and particle clutter.
- MEDIA: editable layered menu panorama16:9; adapt framing for16:10/ultrawide rather than stretching; character layer and logo separate; title/action safe area; icons as real vectors with consistent weight and meaningful silhouettes. Loading screens use actual map art/one short useful tip.

### Gaps
Refero style catalog is predominantly marketing pages, not game front ends; therefore scene/menu composition is an informed adaptation. References do not establish retention uplift. No licensed replacement font selected and no artwork generated in this pass.

## What production and acceptance work makes this plan executable?

### Takeaway
Implement one end-to-end player journey first, then reuse its input/state contracts across modes. A polished menu is not complete until loading, failure, device loss, save outcomes and rematch work in the packaged build.

### Cited Findings
- Current general showScreen focuses the first visible broad selector, while menuBack only finds data-back; custom screens implement their own state. This supports an explicit shared focus/back lifecycle rather than cosmetic-only reskin. [index.html2607–2610](https://github.com/joshharris-sparkedfm/custard-knights/blob/6f1300b6f5e7dab9f31b684e60d1cadd2bbc5842/index.html#L2607), [index.html2859–2867](https://github.com/joshharris-sparkedfm/custard-knights/blob/6f1300b6f5e7dab9f31b684e60d1cadd2bbc5842/index.html#L2859).
- Adobe connector metadata confirms vector render/export (AI→SVG/PNG), raster crop/resize, image edit, font discovery/preview, video timeline/render and speech enhancement are available tools. This was capability inspection only; no assets uploaded/modified. The Adobe template skill requires a user-selected template; it is appropriate to promotional layouts when needed, not an excuse to turn this game into an Express template. [Adobe template skill](C:/Users/Joshua/.codex/plugins/cache/openai-curated-remote/app-69312da8e4dc81919370cb86fd172b6c/10.0.0/skills/adobe-design-from-template/SKILL.md), [Adobe fonts skill](C:/Users/Joshua/.codex/plugins/cache/openai-curated-remote/app-69312da8e4dc81919370cb86fd172b6c/10.0.0/skills/adobe-fonts/SKILL.md).

### Inferences / proposed delivery order and done-when
A. Navigation/state foundation + menu composition: implement home, options, mode selection, lobby, loading, pause, result as one coherent route. Acceptance: fresh profile and existing profile; keyboard only, mouse only menus, Xbox-style pad, mixed couch devices; every action reachable, no hidden focus, no stale pressed inputs, Back retains correct state; unchanged legacy ownership and narrative checkpoint.
A2. Couch/social acceptance is first-class: read labels, player rings, score and countdown from normal TV distance; use the XAG console-size reference as a test target rather than only desktop font sizing. Distinguish each seat by number/name/shape as well as colour. Mixed keyboard/pads retain ownership after reconnect, wardrobe changes, rematch and scene changes. Each device can ready its own seat; the host alone changes shared rules; an unassigned controller cannot trigger two seats. Test two people sharing keyboard plus two pads, pad enumeration changes, one player leaving, and rejoining between rounds. State explicitly that a late online arena arrival waits for next round and a late Cup arrival waits for next Cup; do not advertise seamless drop-in. Offer the same understandable setup summary across couch and online rather than maintaining contradictory rules pages.
A3. Longevity comes from frictionless repeated social sessions: preserve party, settings and cosmetics across a run; offer another round immediately, a three-round Cup as a short commitment, optional earned goals and readable variety. Remember the group's last setup locally. Add content only after observed replay demand; do not rely on daily chores, currencies, an uncalibrated ranked score, or flooding the menu with modes. Treat party survival/rematch completion as measurable outcomes, not fabricated retention.
B. First15minutes: first launch → one guided opportunity to move/aim/hit/block/dash → real round → understandable result → rematch/wardrobe. Human validation asks players to explain objective and controls without coaching; observe confusion and voluntary replay. Targets such as first meaningful input within60seconds are design goals, not measured claims. Exclude automation/QA from human reporting.
C. Social loop: two actual PCs/networks → invite → same lobby → round → result → rematch → host departure. Test invalid/expired code, fullroom, version mismatch, slow asset loading, late arrival, failed copy, losing connection, losing controller. Record which recovery paths exist per transport.
D. Collection and continuity: earn once, choose/skip reward, change outfit, show that outfit in match, restart, import older backup. Failed disk/storage case must report failure, no reward loss or duplicate award. Controller focus returns to equipped item.
E. Art production: build one hero menu and one faction-selection screen mock with current models first. Adobe vector/export can produce consistent icons/capsule crops once art direction is locked; game controls/text remain live code. Higgsfield belongs to approved cinematic moments after existing-video recovery and storyboard lock; it cannot fix poor menu states or substitute for gameplay. Preserve editable originals and provenance; atlas/socket/grip completeness required for new faction models.
F. Package visual/device pass: screenshot first launch/home/setup/lobby/story/map/wardrobe/results/options/error states at1280x720,1920x1080,16:10 and wider; inspect100/150/200percent OS scaling and text scale; measured HUD readability, no offscreen actions, no frame drops from menu animation. Real physical controller/Steam Input and secondPC acceptance still required. Default UI shouldn't require scrolling for Resume/Continue/Back; long collection grids can scroll with visible focus.
G. Release gate: no P0 blocked navigation/save/data loss/softlock; no misrepresented online service; human review says objectives understandable and rematch enjoyable; correct art and input glyphs throughout. Report bugs by reproduction/build/expected/actual, not raw assertion totals. Stable private beta precedes storefront polish/public sales.

### Gaps
No actual user/device testing was conducted. Performance/minimum hardware, public service deployment and Steam release requirements are covered by another researcher. Adobe generation/export permissions, quotas and final asset quality were not exercised; available tool names are not a successful production job.
